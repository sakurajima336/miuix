## ② 新组件明细

### 2.1 COUIAlertDialogBuilder —— 通用 AlertDialog 构建器族 ⭐⭐⭐

**类**：`com.coui.appcompat.dialog.COUIAlertDialogBuilder`（Contacts；设置/电话/Gallery 同在）
**同族**：`COUIAlertDialogOverlayHelper`（遮罩）、`COUIBottomAlertDialogAdjustUtil`（底部式对话框窗口调整）、`dialog.widget.COUIAlertDialogRootLayout/MaxLinearLayout/MaxScrollView/ClipCornerLinearLayout/MessageView/COUIDialogTitle/COUIMaxHeightNestedScrollView`、`dialog.adapter.COUIListDialogAdapter/ChoiceListAdapter/ChoiceListCursorAdapter/SummaryAdapter`、`dialog.olivelink.DialogShadowEdgeParams`。

**功能**：ColorOS 全量 AlertDialog：居中式/底部式（Bottom AlertDialog）/跟随手指（Follow-Hand）三种窗口形态，大屏/折叠屏/小窗自适应，支持列表、单选、Loading、摘要行（SummaryItems）、背景模糊。

**关键 API**（源码方法签名，`COUIAlertDialogBuilder`）：
```java
create(): androidx.appcompat.app.AlertDialog
create(android.view.View, int, int)              // 自定义内容 + gravity/anim
createWithExtraOffset(android.view.View, int, int, int, int)
setPositiveButton/Neutral/NegativeButton(CharSequence, OnClickListener, boolean)  // 第三参=推荐按钮
setRecommendButtonType(com.coui.appcompat.button.COUIButton$ButtonType)
setSingleChoiceItems(ListAdapter, int, OnClickListener)
setSummaryItems(CharSequence[])                  // 消息下方灰色摘要行（ColorOS 特有）
setAnchorView(View) + setAlwaysFollowHand(boolean)   // 跟手模式
setBlurBackgroundDrawable(boolean)               // 背景模糊
setWindowGravity(int) / setWindowAnimStyle(int)
show(): AlertDialog
```

**样式属性**（`initAttrs` 反编译，`R$styleable.COUIAlertDialogBuilder`）：
```java
obtainStyledAttributes(null, R$styleable.COUIAlertDialogBuilder, DEF_STYLE_ATTR, DEF_STYLE_RES);
// attr: android:gravity(默认17=居中), windowAnimStyle, contentMaxWidth, contentMaxHeight,
//       customContentLayout, isNeedToAdaptMessageAndList, isTinyDialog, hasLoading,
//       isAssignMentLayout, isForceCenterStyleInLargeScreen, isCustomStyle
```

**窗口初始化**（`initWindow`）：
```java
if (isFollowHandMode()) {
    COUIBottomAlertDialogAdjustUtil.adjustToFree(window, mAnchorView, mAnchorViewTouchPoint, mExtraOffsetPoint);
    window.getDecorView().setVisibility(4);   // 先隐藏，等定位完成再显示
} else {
    updateGravityAndAnimation(configuration);
}
window.getDecorView().setOnTouchListener(new OutsideTouchListener(mDialog));
setWindowType(window); setWindowWidth(window);
```

**视觉/交互细节**：
- 字段含 `mBackgroundBlurBuilder`（COUIBackgroundBlurBuilder）、`mDialogWindowType`、`mContentMaxWidth/Height`、`mIsTinyStyle`（小窗 Tiny 样式）、`mIsForceCenterInLargeScreen`、`mRecommendButtonId/mRecommendButtonType`（推荐按钮高亮）。
- 无障碍：`initAccessibilityFeatures` 挂 AccessibilityManager + TouchExplorationStateChangeListener，触摸探索模式下切换对话框布局（`updateAccessibilityState`）。
- 配置变化：`registerApplicationConfigChangeListener` 监听旋转/折叠，`updateGravityWhileConfigChange` 重算 gravity 和动画资源。
- 阴影：`dialog.olivelink.DialogShadowEdgeParams` 是 Kotlin data class，12 个 Float 参数：`lineAlpha/lineAngle/lineWidth/fadeAlphaX/fadeAlphaY/fadeWidthScale` 各有 dark 变体（darklineAlpha 等），与 coui-core `CouiShadowEdgePacking` 同源。

**对照 coui-core**：完全没有对应物（coui-core 只有 PopupListWindow 一支）。这是移植价值最高的一类——ColorOS 所有 App 的确认框都走它。KMP 移植要点：Builder API + 三种形态（Center/Bottom/FollowHand）+ 推荐按钮 + 摘要行；Follow-Hand 定位逻辑可复用 coui-core CouiPopupLocateHelper 思路。

### 2.2 COUISecurityAlertDialogBuilder —— 安全确认对话框 ⭐⭐

**类**：`com.coui.appcompat.dialog.COUISecurityAlertDialogBuilder`（Contacts）
**字段**：`mHasCheckBox, mIsChecked, mCheckBoxString, mStatementId, mLinkId, mIsShowStatementText, mOnSelectedListener, mOnLinkTextClickListener, mPredictiveBackCallback, DELAY`。

**方法体证据**（`init/initStatementText`）：带复选框（"不再提示"）+ 富文本声明（SpannableStringBuilder 链接可点，`getStatementStringBuilder(String,int,int)`），`configureDefaultPredictiveBack()` 注册预测性返回手势回调。

**API**：`setCheckBoxString/setChecked/setHasCheckBox/setNegativeString/setNeutralString/setOnLinkTextClickListener/create()`。
**用途**：权限/安全敏感操作二次确认（如"允许联系人读取?"带不再提示勾选）。
**对照**：无对应物；可做成 `CouiSecurityAlertDialog`（AlertDialog 变体 + checkbox + linkSpan + predictive back）。

**动画核心**（`doTranslationAndScaleSpringAnimaion`，Java 反编译）：
```java
// 位移+缩放一体弹簧；AnimationFlag: 1=TRANSLATION, 4=SCALE, 2=ALPHA, 8=OUTSIDE_ALPHA
if (hasAnimationFlag(1)) mSpringForceTranslationAndScale.setResponse(getTranslationResponse());
else if (hasAnimationFlag(4)) setResponse(0.25f);            // 进入/退出都 0.25
// 缩放进度: 进入 scale = 0.8f + progress*0.2f；退出 scale = 1.2f - progress*0.2f
float f4 = mIsEntering ? (f3*0.2f)+0.8f : ((1.0f-f3)*0.2f)+0.8f;
mDesignBottomSheetFrameLayout.setScaleX/Y(f4);
// minimumVisibleChange: 显示 1.0f, 消失 10.0f（更快收敛）
mTranslationAndScaleSpringAnimation.setMinimumVisibleChange(mIsEntering ? 1.0f : 10.0f);
setStartValue(mStartValueOfTranslateAnimation);              // 0
animateToFinalPosition(mIsEntering ? end : end + 1.0f);       // end=100（setDefaultSpringStartEndValue: 0→100）
```

**响应值动态计算**（`getTranslationResponse`）：
```java
if (mIsEntering) response = 0.45f;
else response = 0.18f /* = DEFAULT_TRANSLATION_HIDE_SPRING_RESPONSE_LARGE */;
// 再按面板可见高度分档：面板越高 response 越小（越"硬"），peek/half/expanded 三态取不同高度基准
```
**弹簧初始化**（`initTranslationAndScaleSpringAnimation`）：`bounce = 0.0f`（无回弹）。

**Behavior 状态**（`COUIBottomSheetBehavior` 字段）：STATE_HIDDEN/EXPANDED/COLLAPSED/HALF_EXPANDED/DRAGGING/SETTLING + `SETTLE_ANIM_SPRING_BOUNCE/RESPONSE`、`HIDE_THRESHOLD/HIDE_FRICTION`、`PULL_UP_DY_THRESHOLD/PULL_UP_SPEED_THRESHOLD/PULL_UP_FRICTION`、`DRAG_TO_HIDDEN_SPEED_THRESHOLD`、`SHAKE_HAND_MOVING_BASE_UP/DOWN_VELOCITY`（"握手"跟随动效）、`CORNER_ANIMATION_DURATION`、`DEFAULT_PHYSICS_DAMPING_RATIO/DEFAULT_PHYSICS_FREQUENCY`、`BOTTOM_DISPLAY_VIEW_HEIGHT_LONG_TO_SHORT` 等（折叠屏展开态切换高度动画）。

**资源引用**（`initValueResources`）：


**其他交互**：`dispatchTouchEvent` 接管、背景模糊 `doBlur/setBackgroundBlur(boolean, AnimLevel, boolean)`、阴影像素级绘制（SHADOW_EDGE_FADE_ALPHA_IN_LIGHT/DARK 等常量，与 DialogShadowEdgeParams 对应）、导航栏颜色动画 `createNavigationColor(int)`（NAV_COLOR_ANIM_DURATION）、背传穿透 `enableBackEventPassThroughForDismiss/setBackEventPassThroughWhileDismissing`、触觉反馈 `getCanPerformHapticFeedback/doFeedbackAnimation(View)`、帧率控制 `setFrameRate(spring)` + `AnimationVelocityCalculator`（速度跟踪）。

**对照 coui-core**：无对应物。**最高优先级**。KMP 移植要点：
- Compose 用 `AnchoredDraggable` + spring(bounce=0, response 动态 0.18~0.45) 复刻；scale 0.8→1.0 联动；
- 半展开态（halfExpandedRatio）、peek 高度、手势导航 inset、IME adjustResize 三态适配都要建模；
- 面板高度变化时的高度弹簧 `createContentChangeSpringAnimation`（SPRING_ANIM_CONTENT_CHANGE_BOUNCE）。

### 2.12 RegionBasedLongPressDetector / PreciseLongPressHelper —— 弹窗菜单精确长按检测 ⭐⭐⭐

**类**：`com.coui.appcompat.poplist.RegionBasedLongPressDetector`（28 字段、5 内部类）、`PreciseLongPressHelper`、`PreciseClickHelper`。

**状态机**（字段+反编译方法）：`STATE_IDLE(0) / STATE_DETECTING(1) / STATE_TRIGGERED(2)`，`INVALID_POSITION_DATA_INDEX, LOCATION_COMPONENT_COUNT`。

**核心逻辑**（`handleTouchEvent`）：
```java
DOWN  -> startDetection(x, y)
MOVE  -> updatePosition(x, y)
UP/CANCEL -> 清 mLastTriggeredParent/mLastTriggeredPositionDataIndex, stopDetection()
```
`startDetection`：`mResolver.resolve(rootView, x, y)` 返回 `Target{view, hasSubMenu, isSubMenuAnchor, positionDataIndex}`——**按命中区域解析目标**（不是按 View 层级），只有子菜单锚点/有子菜单的项才触发长按；同一条目连续触发去重（`mLastTriggeredParent` 比对 parent+position+isSubMenuAnchor）。
`updatePosition`：移出目标矩形 → 取消 pending、回 IDLE、回调 `onDetectionEnded()`；移入子菜单锚点 → `tryScheduleAnchorLongPress`（带 `mAnchorSlopExceeded` 判定：锚点需先超过 touchSlop 才算有效）。
`scheduleLongPress`：`mRootView.postDelayed(runnable, mLongPressTimeout)`，timeout 来自 `getLongPressTimeout()`。

**PreciseLongPressHelper**：包装单个 View（`setup()` 给 target 挂 OnTouchListener，DOWN 记录 `mLastTouchDownXY`，长按回调带精确坐标 `OnPreciseLongClickListener`），支持 `mTouchListenerTransfer` 把触摸事件转发给别的处理器（配合 submenu 场景）。

**对照**：coui-core 有 `CouiPopupGesture`/`CouiPopupTouchMotion`，但**没有"区域解析式长按检测"**——现有实现绑定在 item View 上，而 ColorOS 这套是 root 层按坐标 + 位置数据（RecyclerView positionDataIndex）解析目标，子菜单展开后长按父锚点还能续接（`mSubMenuJustEnteredNoMoveYet` 防抖）。KMP：用 `awaitPointerEventScope` 在 Popup 根层做区域命中 + timeout 检测，可统一父/子菜单长按逻辑。**移植价值高**（现有 TouchMotion 的长按路径可替换）。

### 2.16 PopupMotionTrajectoryUtil —— 菜单手势贝塞尔运动轨迹 ⭐⭐⭐

**类**：`com.coui.appcompat.poplist.PopupMotionTrajectoryUtil` + `animation.bezier.BezierGravityConfig / BezierGravityEndpoints / BezierGravityPathGeometry / BezierGravityPathMath`（全部在 Contacts/设置 APK）。

**核心**（`snapshot` 反编译）：
```java
public static Snapshot snapshot(COUIPopupListWindow win, PopupGravityMotionParams params) {
    PopupMenuDomain domain = win.getLocateHelper().getDomain();
    float[] d = { domain.mLastPathAnchorX - domain.mMainMenu.centerX(),
                  domain.mLastPathAnchorY - domain.mMainMenu.centerY() };   // 手指→菜单中心向量
    BezierGravityConfig cfg = new BezierGravityConfig(
        params.getGravityDistanceMinPx(), params.getGravityDistanceMaxPx(), params.getGravityArcMaxPx());
    float p1t = clamp(params.getP1T(), 0.05f, 0.95f);   // BEZIER_T_COERCE_MIN/MAX
    float p2t = clamp(params.getP2T(), 0.05f, 0.95f);
    geometry = BezierGravityPathMath.controlPoints(
        new BezierGravityEndpoints(d[0], d[1], 0, 0), cfg, p1t, p2t);   // 三次贝塞尔控制点求解
    snapshot.geometry = geometry;
    snapshot.menuCenterScreenX/Y = contentView.getLocationOnScreen() + domain.mMainMenu.center();
    snapshot.resolvedPathAnchorSlot = domain.mResolvedPathAnchorSlot;
    snapshot.pathAnchorMode = domain.mPathAnchorMode;
}
```
**含义**：菜单展开后手指拖动时，菜单不是 1:1 跟手，而是沿一条**三次贝塞尔"重力曲线"**滑向手指（带最小/最大重力距离和最大弧度限制，P1/P2 控制点参数 t 钳制 0.05~0.95），松手后菜单吸附回锚点——即 ColorOS 弹窗菜单的"果冻跟手"手感。
**对照**：coui-core 有 `CouiPopupTransitionDriver`/`CouiPopupGesture`，但未含贝塞尔重力轨迹数学（BezierGravityPathMath.controlPoints）。**这是本分类最有移植价值的新算法**：纯数学，可直接 Kotlin Multiplatform 化（4 个类 + PopupGravityMotionParams）。
