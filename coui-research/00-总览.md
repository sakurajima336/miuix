## ④ 跨分类共性发现

1. **统一的弹簧参数体系**：全部 6 份报告的动效实测值都落在同一 response/bounce 参数化上（stiffness=(2π/response)²、dampingRatio=1−bounce，与 coui-core `CouiSpring.kt:95` 公式逐字一致）。高频实测值：state 遮罩/SnackBar show/拖拽 = 0.3/0；BottomSheet 进入 0.45/退出 0.18、bounce=0；ToolTips 0.4/0.2；ChipGroup 0.35/0；FloatingToolbar 0.5/0.4；toggle 0.3/0.4；progressbar 弹簧用传统 stiffness=50、damping=1.0。移植时全库只需一套 CouiSpring 换算。
2. **按压反馈双方案 + 保底机制**：scale 方案（FAB 0.9 缩放 200ms→回弹 340ms，报告 04）与亮度 tint 方案（1.0→0.8 200/340ms，报告 05 的 resolver 版），都带"快速点击保底进度"分档（getGuaranteedAnimationValue：高度 ≥600→0.993、≥156→0.965、否则 0.99）。
3. **液态材质四件套贯穿全库**：blur/caustic shadow/spotlight/stroke（报告 02 ChipTab+SearchBar、03 FloatingToolbar、04 FAB+Button、06 com.oplus.view.material 门面）；Java 层只有参数（OplusMaterialMetaBallParams 等），真实算法在 17MB libhwui.so（hwui-probe 无 dex，native 未逆向）。
4. **官方性能取向是"值更新脱离主线程"**：RenderThreadAnimationExecutor（01）、OplusAsyncPropertyUpdateStrategy/RtViewWrites/PopupMotionAnimateKitController RT 混合写入（05）、rtscroll/OplusRenderNodeAnimator（06）层层印证；对应 KMP 规范即 `Modifier.graphicsLayer { }` 单点消费 state。
5. **olivelink/RUS 远程参数下发体系**：COUISwitchParams 运行期覆盖（05）、OplusSpringOverScroller.setSpringConfigFromRus 五段配置（06）、SearchBar params High/Low 双档 + olivelink 子包（02）——官方参数全部对象化，天然适合 KMP data class。
6. **三层结构清晰**：app 层 `com.coui.appcompat.*` ↔ framework 层 `android.widget.*Oplus*/com.oplus.*`（经 SocExt/Ext 接口注入 AOSP）↔ native libhwui.so。app 层常与 framework 层有孪生类（COUISpringInterpolator、SpringOverScroller、PopupListWindow）。
7. **probe 资产两两重复**：device-framework-probe≡framework-dex-probe（14019 类逐项相同）、oplusfw-probe≡oplus-fw-dex-probe（3507 类相同），后续扫描只需各看一个。
8. **普遍的取证限制（6 份报告 issues 共性）**：`static final` 常量编译期内联 + REA 对 `<clinit>`/多 overload 方法反编译失败，导致一批常量"未确认"（BottomSheet DEFAULT_SPRING_*、SpringOverScroller DEFAULT_STIFFNESS、FLING_SPEED_INCREASE_RATE、COUISpringInterpolator.DEFAULT_*、FAB DEFAULT_SPRING_*、LoadingButton DOT_*_ALPHA 等）；apktool 缺失导致 dimen/color 具体值多未解码（04 报告改用 aapt2 dump resources 部分补救）。这些值不影响结构移植，落地前需真机/RUS 对照。

## ⑤ 移植路线图建议（按依赖关系排序）

**阶段 0 · 动效基座（报告 05 优先结论）**——其他一切组件都依赖它：
1. `CouiSpringData` 补 `blendDuration`（responsiveSpring）+ `visibilityThreshold = |target−current|/10000`（COUIResponsiveSpringMotion 行为）；
2. `CouiCurves` object（spring/linear/easeInOut 300ms 默认/cubicBezier）；
3. `COUISpringInterpolator`（物理式插值器，欠阻尼分支 + f(1) 归一化）；
4. `RSSpringModel.estimateDuration`（欠阻尼分支）用于手势预测；
5. `COUISwitchParams` 官方默认值 + BezierGravityConfig(30,400,80) 入 `CouiMotionTokens`；
6. `CouiPressStyle.Brightness` 变体（200/340ms + 分档保底值）。

**阶段 1 · 状态与输入底座**（阶段 0 完成后，被最多组件引用）：
1. **state 状态引擎**（04）：StateEffectAnimator（response=0.3/bounce=0）→ COUIMaskEffectDrawable 三通道 → MaskRipple/StateEffectDrawable 组合，落地为 `CouiStateEffectModifier`；后续 Tab/CheckBox/Chip/FAB/按钮全部复用；
2. **COUIEditText 底座**（02）：BasicTextField + 自绘 box + 浮动 hint + 250ms 删除图标；InputView/Card/Code/LockScreen/SearchView 全部建在其上；
3. BezierGravityPathMath 弹道（01+05 合并项）：4 个纯数学类直接 KMP。

**阶段 2 · 高频独立组件**（只依赖阶段 0/1）：
- 弹窗三件（01）：COUISnackBar（参数全）→ COUIAlertDialogBuilder → COUIBottomSheetDialog（弹簧参数全提取，最大单体）；
- 按钮/进度（04）：COUICheckBox（三态 AVD）→ COUILoadingButton（波形完整）→ HorizontalProgressBar → CircularProgressBar（spring 1f/50f）→ COUIFloatingButton；
- 导航（03）：COUITabLayout（果冻指示器）→ COUIPageIndicatorKit；
- 选择（02）：COUINumberPicker（DatePicker/TimePicker 复用它）→ Chip/ChipGroup（弹簧 0.35/0）。

**阶段 3 · 复合与框架级**：
- 滚动物理（03 SpringOverScroller RK4 fling + 06 framework 三件套起步弹簧/分带摩擦/springBack）→ Compose flingBehavior；
- COUISpringDragHelper 拖拽/吸附双弹簧（05）→ 手势组件；
- statement 族、ToolTips、tips、RegionBasedLongPressDetector（01）；
- ResponsiveUI 引擎 + COUIGridLayout + ListDetailView（03）；
- COUISearchBar 状态机模型（02）与 COUIBottomFloatingToolbar（03）；
- COUIAutoCompletePopupWindow、DatePicker/TimePicker、ChipTab、Banner、OplusScrollBarEffect tokens。

**阶段 4 · 观望/低优先**：animatekit DSL/strategy/target 层（按类移植价值低，语义作 API 设计约束）、RT 写入约定、metaball/caustic shader（需自研 AGSL，算法在 native 不可见）、COUIRotating* 旋转族、COUIIsolatedPopupListWindow（Compose 原生免费）、OplusPopupListWindow（对照用）。
